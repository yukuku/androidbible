# REM-31: Migrate InternalDb to Room (SyncShadow + SyncLog Tables) ✅ COMPLETED (2026-05-15)

**Addresses:** TD-02 (final step in the [REM-10](REM-10-room-markers.md) / [REM-11](REM-11-room-version.md) / [REM-27](REM-27-room-devotion.md) / [REM-28](REM-28-room-per-version.md) / [REM-29](REM-29-room-progress-mark.md) / [REM-30](REM-30-room-reading-plan.md) chain)
**Module:** Storage — Sync subsystem
**BRICE:** B=3 R=3 I=2 C=3 E=5 → **3.2**
**Phase:** 2 — Architecture Improvements

**Outcome.** The last two hand-rolled `AlkitabDb` SQLite tables — `SyncShadow` and `SyncLog` — are now backed by Room in `AlkitabRoomDb` (the same separate-file Room database introduced by REM-11 and extended by REM-10/REM-27/REM-28/REM-29/REM-30). `AppDatabase` bumped `version = 6 → 7`; the SQL inside `MIGRATION_6_7` mirrors what Room's entity definitions emit (verified by `MigrationTestHelper.runMigrationsAndValidate` with `validateDroppedTables = true`).

Two tables, one DAO: both belong to the sync subsystem and are commonly written together during sync application (a successful sync push writes a new shadow and appends an `apply_result` log row). The Room DAO preserves the legacy facade's count-then-update-or-insert upsert via a `@Transaction`-annotated `insertOrUpdateShadow`, matching the legacy `SQLiteDatabase.beginTransactionNonExclusive` semantics — a UNIQUE constraint on `syncSetName` was *not* added because the legacy `index_SyncShadow_01` is non-unique and a duplicate row in the legacy table would crash the migration on index creation.

**Shipped:**
- **Entities:** `SyncShadowEntity.kt` mirrors the legacy schema (`syncSetName: String NOT NULL`, `revno: Int NOT NULL`, `data: ByteArray?`) with a non-unique index on `syncSetName`. The entity overrides `equals` / `hashCode` to use content-equality on `data` so round-trip assertions in the unit tests are reliable. `SyncLogEntity.kt` mirrors the legacy log columns (`createTime: Int NOT NULL`, `kind: Int NOT NULL`, `syncSetName: String?`, `params: String?`) with a non-unique index on `createTime`. `createTime`/`kind`/`syncSetName` for shadow are non-nullable in Room even though the legacy schema permitted NULL; `SyncShadowDataMigration` drops any legacy row missing the keyed column rather than coalescing — coalescing multiple legacy NULLs would cause logic ambiguity at the facade keyed-lookup level (the same defence-in-depth pattern as REM-30).
- **Room DAO:** `SyncShadowRoomDao.kt` exposes the seven SyncShadow primitives (`insertShadow`, `findShadowBySyncSetName`, `findRevnoBySyncSetName`, `findShadowSummaryBySyncSetName`, `updateShadowBySyncSetName`, `deleteShadowBySyncSetName`, `countShadowsBySyncSetName`) plus the transactional `insertOrUpdateShadow`, and the three SyncLog primitives (`insertLog`, `listLatestLogs`, `countAllLogs`). The `findShadowSummaryBySyncSetName` projection returns `(_id, revno, length(data))` so the chunked blob read in the facade can size its `ByteArray` and walk the row in 1 MB chunks without loading the full blob in a single Room cursor.
- **Schema bump:** `AppDatabase.kt` now `@Database(version = 7)` with `@JvmField val MIGRATION_6_7`. `Alkitab/schemas/yuku.alkitab.base.storage.room.AppDatabase/7.json` is checked in alongside `1.json` through `6.json`.
- **Data migration:** `SyncShadowDataMigration.kt` — idempotent one-time copy from the legacy `SyncShadow` and `SyncLog` tables into Room. Idempotency uses the persistent `Prefkey.sync_shadow_data_migration_v1_done` flag (same approach as REM-10/REM-11/REM-27/REM-28/REM-29/REM-30 post-#198), so a user who clears a shadow from the sync-settings screen cannot resurrect it on the next launch. Streams rows from each legacy cursor into Room inside a single `runInTransaction`. The `data` BLOB column can be multiple megabytes (Mabel snapshots routinely cross the 2 MB CursorWindow cap), so streaming bounds memory by the largest single row rather than the sum of all rows. Wired into `S.kt`'s `db` lazy initializer as the seventh migration call.
- **Facade preservation:** `SyncShadowDao.kt` rewritten to delegate to the Room DAO. Public method signatures unchanged — the seven facade methods called from `InternalDb` (`getBySyncSetName`, `getRevnoBySyncSetName`, `insertOrUpdateBySyncSetName`, `deleteBySyncSetName`, `insertLog`, `listLatest`) did not need to be touched. The chunked `substr()` blob read remains the workaround for the Android CursorWindow 2 MB cap, but now runs against Room's `SupportSQLiteDatabase` handle via `roomDb.openHelper.readableDatabase` rather than the legacy `InternalDbHelper` — Room cannot express chunked cursors natively, so this single path drops down to raw SQL. Every other read/write goes through the generated DAO.
- **Legacy tables left in place.** `SyncShadow` and `SyncLog` are still created by `InternalDbHelper.onCreate` (and the legacy upgrade-path SQL for `oldVersion <= 14000170` / `oldVersion < 14000173` is untouched) so the rollback safety net is preserved; a future release can drop them once the Room path has baked.

**Tests (3 new files, 1 existing extended):**
- `SyncShadowRoomDaoTest.kt` (14 tests) — Room-level primitives: insert + round-trip every column, find-by-name (null + present), find-revno (null + present), find-summary (`_id` / `revno` / `dataLen`), summary on null blob reports zero, transactional `insertOrUpdateShadow` insert-vs-update branches and idempotency, delete-by-name + remaining-row count, null + empty `data` round-trips, insertLog with assigned `_id`, `listLatestLogs` DESC + maxrows + empty, null `syncSetName`/`params` round-trip.
- `SyncShadowDataMigrationTest.kt` (11 tests) — empty/empty no-op, shadows copy with every persisted field, logs copy, drop legacy shadow rows with NULL `syncSetName`, idempotency, fresh `_id` assignment, issue #195 resurrect-guard, fresh-install flag set, successful-copy flag set, both upgrade-path branches (`countAllShadows > 0` and `countAllLogs > 0`).
- `SyncShadowDaoTest.kt` (8 tests) — Facade-level parity gate: missing-row null, insert + round-trip, in-place update (no duplicates), revno (0 default + present), delete + unrelated-set survival, **3.5 MB blob round-trip** exercising the chunked `substr()` read path, EventKind / params Map round-trip through Gson, `listLatest` newest-first + maxrows.
- `AppDatabaseMigrationTest.kt` — added `migrates6To7` test plus an end-to-end `v1 → v7` open-via-Room round-trip; updated every `Room.databaseBuilder` call to register `MIGRATION_6_7` now that the entity-driven schema is at v7.

**Verification.** `./gradlew :Alkitab:assemblePlainDebug :Alkitab:testPlainDebugUnitTest :Alkitab:testPlainReleaseUnitTest` — all green.

**Difficulty:** Easy. Took ~half a day with the REM-10 / REM-11 / REM-27 / REM-28 / REM-29 / REM-30 pattern already established. The new wrinkle was preserving the chunked `substr()` blob read: Room can't express chunked cursors natively, so the facade keeps a thin raw-SQL escape hatch against `roomDb.openHelper.readableDatabase`. With REM-31 done, every InternalDb table has been migrated to Room; the legacy `InternalDbHelper` now exists purely as a rollback safety net.
